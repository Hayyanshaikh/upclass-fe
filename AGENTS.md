# Frontend Agent Instructions

## Design Instructions

Before creating or changing frontend screens or components, read and follow [`.design.md`](./.design.md).

It defines the shared theme, spacing, component reuse, styling conventions, and code organization rules. Follow these guidelines consistently across the frontend.

## API Integration & Orval

- Backend API schemas and DTOs are the source of truth.
- Whenever backend API schemas or DTOs change, regenerate the frontend API client by running:

  ```bash
  npx orval
  ```

- Always use the API functions, React Query hooks, and types generated by Orval.
- Do not manually create API hooks when an equivalent Orval-generated hook exists.
- Do not manually write `fetch` or `axios` requests for APIs that are already covered by generated Orval hooks.
- Do not manually duplicate request or response DTO types. Import and reuse generated types.
- Use generated query hooks for fetching data and generated mutation hooks for create, update, and delete operations.
- Follow the existing project's API integration and React Query patterns.
- Never modify generated files manually. Make changes in the backend source or Orval configuration, then regenerate.
- If an API or hook is missing, first check the Orval configuration and generated output before implementing an alternative.

## Code Organization

- Follow the existing frontend folder structure and naming conventions.
- Reuse existing components, utilities, hooks, and types wherever possible.
- Avoid unnecessary dependencies and duplicate code.
- Keep components maintainable and focused on their responsibilities.
- Follow the existing project's TypeScript conventions.
- Do not introduce new architectural patterns without a clear requirement.

## General Rules

- Inspect the existing implementation before making changes.
- Do not assume file paths, API response structures, or component behavior.
- Ask for clarification when essential project information is missing.
- Implement only the requested scope.
- Avoid unrelated refactoring or changes.
- After implementation, provide a short summary of changed files and functionality.
